## Структура данных

### Определения
- **Назначение** - документ, выдаваемый врачом, в котором указаны наименования и дозировки льготных лекарств в количестве, рассчитанном на определенный (ограниченный) срок. В одном назначении может быть несколько лекарств. Атрибуты:
  * ID назначения (`id`) - инкрементируемое целочисленное значение, уникальное, read-only
  * Дата назначения (`start_date`)
  * Дата окончания срока назначения (`end_date`), read-only
  * Дата следующего назначения (`next_date`), read-only
  * Назначенные лекарства (`medicines`)
- **Лекарство** (элемент `medicines`) - льготное лекарственное средство, назначенное врачом и выдаваемое аптекой бесплатно на основании назначения. Атрибуты:
  * наименование (`medicines.name`)
  * число таблеток (`medicines.num_pills`)
  * сколько принимать в сутки (`medicines.per_day`)
  * дата, когда лекарство израсходуется (`medicines.depletion_date`), read-only
  * дата, когда нужно получить новую порцию лекарства (`medicines.next_pick_up_date`), read-only
  * получения (`pick_ups`)
У одного лекарства может быть одно и более получений.
- **Получение** (элемент `medicines.pick_ups`) - получение лекарства из назначения в аптеке. Некоторые лекарства из назначения можно получить сразу в полном количестве, указанном в назначении. Некоторые приходится получать частями. Поэтому на одно лекарство в назначении назначение может приходиться несколько получений. Атрибуты:
  * Дата получения (`medicines.pick_ups.date`)
  * Дата следующего получения (`medicines.pick_ups.next_date`), read-only
  * Число полученных таблеток (`medicines.pick_ups.num_pills`)
- **Дата окончания срока назначения** (`end_date`) - это дата самого раннего израсходования лекарства из назначения. Схема расчета:
  * для каждого лекарства в текущем назначении рассчитать дату, когда оно должно закончиться на основании количества, суточной дозировки и даты первого получения в рамках данного назначения;
  * выбрать из полученных результатов лекарство, которое закончится раньше всех;
- **Дата следующего назначения** (`next_date`) - это дата, когда нужно получить у врача новое назначение. Схема расчета:
  * рассчитать `end_date`
  * вычесть двухнедельную дельту из даты, когда закончится это лекарство.
- **Дата получения** (`medicines.pick_ups.date`) - дата, когда лекарство было получено в аптеке
- **Дата израсходования лекарства** (`medicines.depletion_date`) - это дата, когда лекарство, полученное в аптеке на данный момент, физически закончится. Рассчитывается исходя из числа полученного количества (суммы количеств во всех получениях), суточной дозировки и даты первого получения в рамках данного назначения.
- **Дата следующего получения** (`medicines.pick_ups.next_date`) - это дата, когда нужно получить в аптеке новую порцию лекарства в рамках текущего назначения. Рассчитывается относительно каждого лекарства. Схема расчета:
  * рассчитать `medicines.depletion_date`;
  * вычесть недельную дельту из полученной даты.
По итогам полученное значение сохраняется в поле `medicines.next_pick_up_date`.
- **Актуальное назначение** - назначение, у которого `end_date` > даты, на которую сделан запрос.

## Бэкенд
- Python 3.13 / FastAPI
Подкаталог в проекте: `backend`

Прослойка REST API между интерфейсами и файлом на сервере. Имплементация на FastAPI.

API должен работать на том же домене, что и веб-страница, по адресу `/api/`

Доступные эндпойнты и запросы:
- GET `prescriptions/`: выдает список всех записей из `prescriptions.json` (-> 200)
- POST `prescriptions/`: создает новую запись `prescriptions.json`. Для создания в записи обязательно должны быть заполнены:
  * `id` (уникальный ID, целое число, рассчитывается как максимальный ID среди существующих записей + 1)
  * `start_date` (если не заполнено, то автоматически должна подставляться сегодняшняя дата)
В ответ возвращается созданная запись  (-> 201).
- GET `prescriptions/{id}/`: выдает запись с данным `id` из `prescriptions.json`  (-> 200)
- PUT `prescriptions/{id}/`: принимает запись с данным `id`, пересчитывает нужные значения и сохраняет в `prescriptions.json` с обновленными значениями. В ответ возвращается измененная запись. (-> 200)
- DELETE `prescriptions/{id}/`: копирует запись с данным `id` из `prescriptions.json` в `deleted.json`, удаляет ее из `prescriptions.json` и сохраняет оба файла. Если файл `deleted.json` на момент удаления еще не существует, он должен быть создан автоматически. Содержание файла `deleted.json` не должно перезаписываться. Новые записи должны добавляться к старым.  (-> 204)

Значения, которые принимаются при создании или редактировании записей:
- `start_date`
- `medicines.name`
- `medicines.num_pills`
- `medicines.per_day`
- `medicines.pick_ups.date`
- `medicines.pick_ups.num_pills`

Значения, которые не подлежат редактированию или ручному внесению и рассчитываются бэкендом на основании определений выше:
- `id`
- `end_date`
- `next_date`
- `medicines.depletion_date`
- `medicines.next_pick_up_date`
- `medicines.pick_ups.next_date`

Обработка крайних случаев:
- Схема записи сохраняется полностью с предзаполненными значениями `null` в полях верхнего уровня и [] в полях `medicines` и `medicines.pick_ups`
- При сохранении нужно проверять, чтобы значения `num_pills` и `per_day` были числами > 0. Иначе выдавать валидационную ошибку.


## Интерфейсы

### Веб-страница

Подкаталог в проекте: `frontend`

#### Назначение
- представление данных из API
- внесение новых записей через API
- изменение существующих записей через API

#### Стек
- HTML
- CSS
- JS

#### Описание
Страница должна представлять данные из файла `prescriptions.json`, опосредованного API, и отражать его структуру.

- Лого: буква Q с вопросительным знаком внутри
- Заголовок страницы: "Когдашник"
- Цветовая гамма: светлая, четкая
- Стиль: минималистичный, легкий

Ниже заголовка подзаголовок "Назначения".

Ниже аккордеон со списком назначений. По умолчанию развернут только верхний пункт. В свернутом виде выводится только "Назначение от {`start_date`}".

В развернутом виде раскрываются детали назначения. Сверху даты:
- `start_date`
- `end_date`
- `next_date`

Затем вложенный аккордеон, представляющий список лекарств (`medicines`). По умолчанию все элементы списка свернуты. На верхнем уровне выводится: "{`medicines.name`}: до {`medicines.depletion_date`}".

В развернутом виде раскрываются подробности о лекарстве и его получениях. Построчно:

"{`medicines.name`}: до {`medicines.depletion_date`}"  
"Назначено таблеток: {`medicines.num_pills`}, по {`medicines.per_day`} в день"  
"Желательно получить еще к {`medicines.pick_ups.next_date`}" (здесь выводится дата `next_date` из самого позднего `date` получения для этого лекарства)

"Получено:"

Дальше список получений (без аккордеона, просто: "{`medicines.pick_ups.date`}: {`medicines.pick_ups.num_pills`}")

Перед списком назначений должна быть кнопка "Добавить назначение". По щелчку на эту кнопку должна открыться форма приема даты назначения `start_date` с кнопкой "Сохранить".

После этого запись отправляется как POST на `prescriptions/`.

Созданное назначение появляется в списке назначений.

У каждого назначения в развернутом виде есть кнопка редактирования.

По клику на эту кнопку повляется форма ввода. Для тех данных, которые уже заполнены, выводятся исходные значения.

Изменять можно только те значения, которые подлежат изменению. Остальные окна ввода должны быть неактивны.

Список значений, которые можно менять:
- `start_date`

Для лекарств можно вносить и редактировать:
- `name` (название),
- `num_pills` (всего таблеток),
- `per_day` (таблеток в день)

Лекарства добавляются построчно, с помощью кнопки "Добавить лекарство".  
В форме редактирования у лекарства должна быть кнопка удаления.

Для каждого лекарства можно также добавить получения, также построчно с помощью кнопки "Добавить получение".  
В форме редактирования в строчках с получениями должны быть кнопки удаления.

Для получений можно вносить и редактировать:
- `date`
- `num_pills`

При переносе фокуса в форме редактирования данные при изменении (и удалении элементов) внутри назначения данные отправляются через PUT-запрос на `prescriptions/{id}/`.Идентичность записи определяется по ID назначения.

В форме должна быть кнопка "Сохранить". При нажатии на эту кнопку форма редактирования сменяется формой представления, в которой раскрыто то назначение, которое сейчас редактировалось (по ID).

В форме редактирования назначения должна быть кнопка "Удалить назначение". Нажатие на эту кнопку должно вызывать поп-ап с подтверждением удаления. В случае подтверждения отправляется DELETE-запрос на `prescriptions/{id}/`.

## Альтернативные решения
Полноценное веб-приложение с Django-админкой или Фласком, SQLite3

### Плюсы
- Заведомо более расширяемый код
- Более гибкая структура данных 
- Встроенная система аутентификации
- Готовая админка

### Минусы
- Для такого маленького проекта выглядит громоздко

Итог: начинать с простого статического стека с бэкендом и переходить к усложнению только в случае необходимости. В ходе разработки необходимо придерживаться Dependency Inversion Principle (DIP), чтобы можно было с легкостью переключиться на новое хранилище данных.
