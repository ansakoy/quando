# Quando

**Quando** — коллекция скриптов для расчёта даты, когда человеку нужно выписать новое назначение на получение лекарств. Управление через телеграм-бота.

## Идея

По итогам визита к врачу человек получает назначение на получение препаратов на несколько месяцев. Бот хранит список препаратов (название, количество таблеток, приёмов в день) и дату получения. На основе этих данных он рассчитывает:

- когда закончится каждый препарат;
- какой препарат закончится раньше всех;
- к какой дате желательно получить новое назначение (за 14 дней до окончания самого «короткого» препарата);
- сколько таблеток осталось на сегодня.

## Структура проекта

```
quando/
├── bot.py           # Telegram-бот: обработчики команд, точка входа
├── calculate.py     # Расчёты и формирование отчётов, чтение/запись условий
├── parsers.py       # Разбор дат и строк с препаратами из сообщений
├── constants.py     # Константы — ключи YAML-файла условий
├── settings.py      # Настройки (.env), путь к условиям, логирование
├── conditions.yml   # Локальное хранилище данных (создаётся ботом, в git не попадает)
└── pyproject.toml   # Зависимости проекта (управляются через uv)
```

## Установка

Требуется Python **3.13+** и [uv](https://docs.astral.sh/uv/).

```bash
git clone <URL репозитория>
cd quando
uv sync
```

## Настройка

Создать файл `.env` в корне проекта (он исключён из git):

```ini
BOT_TOKEN=токен_вашего_бота_от_BotFather
DEBUG=False
LOG_FILE=quando.log
```

| Переменная   | Обязательна | Описание                          |
|--------------|-------------|-----------------------------------|
| `BOT_TOKEN`  | да          | Токен телеграм-бота               |
| `DEBUG`      | нет         | Режим отладки (по умолчанию `False`) |
| `LOG_FILE`   | нет         | Файл лога (по умолчанию `quando.log`) |


## Запуск

```bash
uv run bot.py
```

Бот работает по long polling и отвечает на команды в личных чатах.

## Команды бота

| Команда     | Назначение |
|-------------|------------|
| `/help`     | Список команд |
| `/hello`    | Поздороваться |
| `/today`    | Отчёт на сегодня: остаток таблеток по каждому препарату, на сколько дней хватит и до какой даты |
| `/report`   | Полный отчёт: дата окончания каждого препарата, что закончится раньше всех, и рекомендуемая дата нового назначения |
| `/date`     | Установить дату получения препаратов |
| `/new`      | Добавить (полностью заменить) список препаратов |
| `/chat_id`  | Показать ID текущего чата |

### `/date` — дата получения

Дату можно указывать в свободном формате, год необязателен (по умолчанию берётся текущий):

```
/date 26.10.2026
/date 26.10
/date 1 окт
/date 01 октября 2026
/date 1 oct 26
```

Поддерживаются числовые (`ДД.ММ[.ГГГГ]`) и текстовые (`Д месяц [ГГГГ] [г.]`) форматы, месяцы — на кириллице и латинице. Несуществующие даты (например, `31.02`) отклоняются с понятной ошибкой.

### `/new` — список препаратов

Данные присылаются **в том же сообщении** после команды, по одному препарату на строку, в формате `название, количество_таблеток, приёмов_в_день`:

```
/new
Лекарство один, 200, 1
Лекарство два, 200, 2
Лекарство три, 180, 2
```

Правила валидации:

- ровно 3 поля через запятую;
- название непустое и не дублируется (без учёта регистра);
- количество таблеток — целое число больше 0;
- приёмов в день — число больше 0, дробные пишутся через точку (например, `0.5`).

Если хотя бы одна строка некорректна, данные **не сохраняются**, а бот перечисляет все ошибки построчно. После успешного сохранения бот присылает подтверждение и напоминает указать дату получения через `/date`.

## Формат данных (`conditions.yml`)

Условия расчёта хранятся в YAML-файле. Файл локальный (в `.gitignore`), создаётся и обновляется самим ботом, но его можно заполнить и вручную:

```yaml
pickup_date: 2026-10-26
data:
  - name: Лекарство один
    num_pills: 200
    per_day: 1
  - name: Лекарство два
    num_pills: 200
    per_day: 2
  - name: Лекарство три
    num_pills: 180
    per_day: 2
```

Запись выполняется атомарно (через временный файл и `os.replace`), поэтому файл не повредится при сбое во время сохранения.

## Логика расчётов

- **Дней хватает на препарат:** `num_pills // per_day` (округление вниз).
- **Дата окончания:** `дата получения + дней хватает`.
- **Следующее назначение:** определяется по препарату, который заканчивается раньше всех; рекомендуемая дата — за **14 дней** до его окончания.
- **Остаток на сегодня** (`/today`): `num_pills − per_day × дней с даты получения`, на утро текущего дня, до приёма сегодняшней дозы. Если дата получения ещё в будущем, остаток считается полным.
