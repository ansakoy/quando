# Quando

**Quando** — система расчёта оптимальных дат получения лекарств и новых назначений: REST API на FastAPI, веб-интерфейс «Quandarium» и Telegram-бот с напоминаниями.

Версия **1.0.0** принципиально меняет интерфейс и структуру данных относительно версии 0.1.0: вместо локального YAML-хранилища бота и ручного ввода препаратов через сообщения используется серверное хранилище назначений (NDJSON), веб-страница для внесения и редактирования данных и полноценный REST API.

## Идея

По итогам визита к врачу человек получает **назначение** на получение препаратов на несколько месяцев. Каждое лекарство в назначении может выдаваться аптекой целиком или по частям — **получениями** (`pick_ups`). На основе количества таблеток, суточной дозировки и дат получений система рассчитывает:

- когда закончится каждое лекарство (`depletion_date`);
- когда нужно получить новую порцию каждого лекарства (`next_pick_up_date` — за 7 дней до окончания);
- какое лекарство закончится раньше всех и когда закончится всё назначение (`end_date`);
- к какой дате желательно получить новое назначение у врача (`next_date` — за 14 дней до `end_date`).

Подробности формул — в [backend/README.md](backend/README.md).

## Архитектура

```
Telegram-бот (bot.py)  ──┐
                         ├──►  REST API /api  ──►  data/prescriptions.jsonl
Веб-интерфейс Quandarium ┘         (FastAPI)       data/deleted.jsonl
```

- **Бэкенд** (`backend/`) — FastAPI, REST-слой между интерфейсами и файловым хранилищем; сам раздаёт статику фронтенда.
- **Фронтенд** (`frontend/`) — статический сайт (HTML + CSS + JS) для просмотра, внесения и редактирования назначений.
- **Бот** (`bot.py`) — запросы отчётов и бэкапов через API, автономная функция напоминаний для крона.
- **Хранилище** — NDJSON-файлы: `data/prescriptions.jsonl` (активные записи) и `data/deleted.jsonl` (архив удалённых с полем `deleted_at`). Доступ сериализуется блокировкой, запись атомарная.

## Установка

Требуется Python **3.13+** и [uv](https://docs.astral.sh/uv/).

```bash
git clone <URL репозитория>
cd quando
uv sync
```

## Настройка

Создать файл `.env` в корне проекта (образец: [.env.example](.env.example)):

```ini
API_URL="http://127.0.0.1:8000"
BOT_TOKEN="токен_бота_от_BotFather"
CHAT_ID=-1001234567890
DEBUG=false
LOG_FILE="quando.log"
SITE_URL="https://quandarium.catabasis.ru/"
TG_USERNAME="TargetUserName"
```

| Переменная    | Обязательна | Описание                                                                                              |
|---------------|-------------|-------------------------------------------------------------------------------------------------------|
| `BOT_TOKEN`   | да          | Токен телеграм-бота. Читается без значения по умолчанию: без `.env` приложение падает при импорте (веб-бэкенду достаточно заглушки) |
| `CHAT_ID`     | нет         | ID группы, куда отправляются напоминания (узнать можно командой бота `/chat_id`; по умолчанию `0`)     |
| `TG_USERNAME` | нет         | Имя пользователя в префиксе напоминания (по умолчанию пустое)                                          |
| `SITE_URL`    | нет         | Адрес веб-интерфейса в тексте отчёта `/api/quando/` (по умолчанию «сайт не указан»)                    |
| `API_URL`     | нет         | Адрес REST API без префикса `/api` (по умолчанию `http://127.0.0.1:8000`). Нужен командам бота и функции напоминания |
| `DEBUG`       | нет         | Режим отладки (по умолчанию `False`)                                                                   |
| `LOG_FILE`    | нет         | Файл лога (по умолчанию `quando.log`)                                                                  |

## Запуск

Из корня проекта:

```bash
uv run python -m backend.main   # API + веб-интерфейс: http://127.0.0.1:8000
uv run bot.py                   # бот в режиме long polling
uv run python bot.py reminder   # разовая отправка напоминания (для крона)
uv run pytest backend/tests     # тесты
```

- FastAPI сам раздаёт статику из `frontend/`, поэтому веб-интерфейс доступен по корневому адресу, а API — по префиксу `/api`.
- Интерактивная документация Swagger: `http://127.0.0.1:8000/docs`.
- Полный перечень эндпойнтов, форматы запросов/ответов и правила расчёта — в [backend/README.md](backend/README.md).

## Веб-интерфейс (Quandarium)

Страница представляет данные из API в виде аккордеона назначений:

- список назначений (по умолчанию развернуто последнее) с датами `start_date`, `end_date`, `next_date`;
- вложенный список лекарств с датой окончания, количеством таблеток, суточной дозировкой и списком получений;
- кнопка **«Добавить назначение»** — форма ввода даты;
- форма редактирования назначения: изменение `start_date`, добавление/удаление лекарств (`name`, `num_pills`, `per_day`) и получений (`date`, `num_pills`); вычисляемые поля доступны только для чтения;
- сохранение по потере фокуса и по кнопке «Сохранить» (PUT-запрос);
- удаление назначения с подтверждением (DELETE-запрос, запись архивируется в `deleted.jsonl`).

## Команды бота

| Команда     | Назначение |
|-------------|------------|
| `/help`     | Список команд |
| `/hello`    | Поздороваться |
| `/quando`   | Отчёт по назначениям из API: когда получать новое назначение и следующее лекарство. Кириллический алиас — `/когда` |
| `/backup`   | Скачать бэкап данных: файлы `prescriptions` и `deleted` из API (альбом из двух файлов, один документ или заметка, если файлов пока нет) |
| `/chat_id`  | Показать ID текущего чата |

Команды обращаются к API по адресу `API_URL` + префикс `/api` и присылают полученный текст как есть с `ParseMode.HTML`. При недоступности сервера бот отвечает сообщением об ошибке и пишет в лог.

### Напоминания

Отдельный режим `reminder` не запускает polling: бот делает один запрос к `GET /api/reminder/` и отправляет полученный текст в группу `CHAT_ID`. Если на сегодня напоминаний нет (API отвечает 404), бот молча завершает работу; любая ошибка (недоступный API, проблемы с отправкой) пишется в лог и не ломает вызов из крона.

Дата сравнивается **точно**: напоминание приходит только в день, совпадающий с `next_date` назначения или `next_pick_up_date` лекарства (серверное время).

Запуск по расписанию (пример: каждый день в 9:00). В кроне минимальный `PATH`, поэтому путь к `uv` лучше указать полностью (`which uv`):

```cron
0 9 * * * cd /путь/к/quando && /полный/путь/к/uv run python bot.py reminder
```

## Деплой

Продакшен-развёртывание на Ubuntu 24.04 (systemd-сервис + nginx с Basic Auth + HTTPS через Let's Encrypt) описано в `deploy/DEPLOY.md`. Каталог `deploy/` в `.gitignore` — конфиги переносятся на сервер вручную.

Ключевые ограничения:

- **один воркер uvicorn**: хранилище сериализует доступ через `threading.RLock` внутри процесса, `--workers N` (N > 1) ломает эту гарантию;
- сайт целиком закрыт HTTP Basic Auth.

## Формат данных

Схема и определения — в [specs/project.md](specs/project.md) и [specs/schema.json](specs/schema.json). Хранилище — NDJSON: одна строка = одно назначение.

```json
{
  "id": 1,
  "start_date": "2026-03-02",
  "end_date": "2026-05-03",
  "next_date": "2026-04-19",
  "medicines": [
    {
      "name": "Препарат А",
      "num_pills": 90,
      "per_day": 1,
      "depletion_date": "2026-06-02",
      "next_pick_up_date": "2026-05-26",
      "pick_ups": [
        {"date": "2026-03-05", "next_date": "2026-05-26", "num_pills": 90}
      ]
    }
  ]
}
```

Вручную вносятся только `start_date`, `medicines.name`, `medicines.num_pills`, `medicines.per_day`, `medicines.pick_ups.date` и `medicines.pick_ups.num_pills`. Поля `id`, `end_date`, `next_date`, `depletion_date`, `next_pick_up_date` и `pick_ups.next_date` рассчитываются бэкендом и при сохранении игнорируются в запросе.

## Логика расчётов

- **Дни запаса лекарства:** `ceil(сумма таблеток получений / per_day)` (минимум 1), отсчёт от даты первого получения. Расчёт выполняется, только если заданы `per_day` и хотя бы одно получение.
- **Дата окончания лекарства** (`depletion_date`): первое получение + дни запаса.
- **Следующее получение** (`next_pick_up_date`): `depletion_date` − **7 дней**.
- **Дата окончания назначения** (`end_date`): минимальный `depletion_date` среди лекарств.
- **Следующее назначение** (`next_date`): `end_date` − **14 дней**.
